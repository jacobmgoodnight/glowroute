## Feature parity and minimum safe migration

| Area | Both at baseline | GlowRoute stronger | Useful older-only behavior / decision |
| --- | --- | --- | --- |
| App/hosting | Static, mobile-first, Leaflet, no user accounts; local data | Build-free vanilla modules, branch-based Pages | Retain GlowRoute architecture. React/Vite/Zod/Cheerio/PapaParse are not needed for the migrated behavior. |
| Routing | Fixed endpoints, optimized stops, Maps links, shares | Exact solver for small matrices, larger heuristic, keyless road routing, backtracking comparisons, budget heuristic with must-see, Live Drive resume/skip/reroute | Older nearest-neighbor/reversal solver and optional keyed routing proxy are not migrated. |
| Personal projects | Favorites, local tours, ratings/notes | Independent holiday/year projects, private backups, import review, approved pins, sophisticated drive feedback | Older tours snapshot displays; do not replace GlowRoute's storage. |
| Discovery | List/map, seasonal data, source links | Curated source-year directory and reviewed updates, safe corrections/removal drafts | Radius/nearest/filter/location workflow reimplemented incrementally in directory; combines this drive's pins and public data. No default city-center routing. |
| Feeds | Source attribution and validation concepts | Directory/project update review protects personal data | Older scheduled HTML adapters, layout checks, 2 MB/15s bounds and snapshots are useful design references. Its enabled flags rely on reported permission; workflow has write/deployment privileges and copies review snapshots into public assets. Reimplement as permission-gated JSON/CSV artifact-only pipeline. HTML remains inactive. |
| Display facts | Source notes, dates, hours, season warnings | Source-review vs season-verification distinction | Optional categories, admission, access, scare, music/FM, accessibility/parking, suggested viewing and structured zoned hours now accepted without changing old validity. No inferred classifications. |
| Scheduling | Time estimates/viewing budget concepts | Existing budget engine and road matrices | Older arrival timeline reimplemented with departure and leave/finish estimates, explicit IANA departure zone and DST fold/gap handling, per-display durations, overnight windows. | Dedupe | Address matching, import checks | Reviewed updates and manual pin/private metadata preservation | Retain multi-source IDs/conflicts. Do not copy older proximity/name merge: nearby houses are distinct. Conflicting stable source identity/address is reviewable. |

| Exports/map | JSON, GPS/map, navigation links | Safe endpoint-redacted sharing; route/map resize and mobile Drive Mode | Add Finish at start. Defer normalized CSV, endpoint-map-pin expansion and Maps-link extraction to keep this change focused. |

The older raw schema uses `lng`, `season`, `sources[]`, nullable unknowns, a default Indianapolis timezone, and globally keyed memories. GlowRoute uses `lon`, project holiday/year, directory source fields and independent display IDs per project. The migration uses optional allowlisted facts, explicitly structured `schedule`, and retains the v2 portfolio store. It never defaults an unknown timezone to Indianapolis, maps cities to coordinates, or treats import time as verification. The complete older snapshot had **307 records, 167 Christmas (original 2025 guide), 140 FrightMaps, zero coordinates**. All 307 were validated as local review input; seven non-numbered Indy location references plus 140 FrightMaps rows stay unlocated. The raw snapshot is not committed or redistributed.

## Implemented user experience

- **Discover displays** extends the existing directory. Search name/street/city/ZIP/area, season/year and existing sort options. Nearby options supply an entered address/coordinates, action-only GPS or an explicit map center; 5/10/25/50-mile radii and nearest sorting use approximate geographic miles. Unlocated entries remain browsable outside radius mode; radius mode excludes them and explains why. Saved project pins join matching directory properties; no bulk geocoding occurs.
- Map pins correspond to current filtered known locations; list rows can show a pin, and pin popups return to the corresponding checkbox. Category, admission, visit style, family and music filters are optional. Missing facts never qualify for filters that require them.
- **Suggest a nearby tour** reviews up to 20 reliable current-project-season candidates, favoring personal preferences and nearby locations. Selected must-see stops survive outside filters/radius or produce a specific constraint error. Apply uses the existing private directory review/confirmation, then the existing road optimizer and optional budget. GPS/search start points remain temporary. An empty finish returns to the search point temporarily; **Finish at start** also works with typed or temporary starts. Suggestions are a starting itinerary, removable/reorderable with existing controls.
- **Departure & visit schedule** is optional. Estimates use mapped OSRM per-leg durations when supplied, otherwise explicitly labeled road-matrix legs. It shows arrival/leave for each stop, total drive/view time and completion including finish/return. Per-stop overrides sit in Details & notes; changes recalculate the displayed schedule without extra routing requests and warn if the retained route exceeds its budget. Re-optimize to reconsider budget selection. Opening checks use each display's own zone and opening day, including overnight seasonal spillover and DST. Incomplete/conflicting/old-season hours stay unknown; sourced but unverified hours are qualified. Live reroutes anchor the remaining schedule to the latest reroute time. No display is automatically removed.
- **Load review snapshot** accepts approved Action artifacts and older Explorer arrays, retains original provider/year/import date, labels unreviewed/stale discoveries, groups exact-address references with conflicts, and excludes city-only locations from route selection. **Load Explorer's older discoveries** fetches only the existing old-repository JSON after a user action; **Paste newer website listings** supports explicit source/year and duplicate-safe weekly manual imports. Same-holiday archives can be checked individually for addition to a newer private project as unverified references, retaining their original season. Applying metadata preserves user name/address unless explicitly replaced, ratings, notes, favorites, mandatory flags and manual pins. Source IDs match across source URLs on the same provider; proximity never merges houses. See [the practical import guide](IMPORTING-LISTINGS.md).
- Weekly/manual import workflow has read-only repository permissions, one serialized five-minute job, bounded requests and seven-day review artifacts. No auto-commit, curated publication or deployment. Failed/empty/malformed imports leave public data untouched and cannot reuse a stale candidate. Both investigated providers are disabled; see [authorization and feed contract](../feeds/README.md).
- [Explorer archive utility](../tools/hde-export.js) downloads the five original local-storage values and complete memory store, including photos/comments/ratings. It is an optional owner-operated read-only utility, not an automatic migration or gallery restore.

## Architecture and compatibility

Pure modules: `display-info.mjs` (optional facts/URL validation), `discovery.mjs` (distance/filter/selection), `candidates.mjs` (review schema/grouping/freshness), `schedule.mjs` (timezones/windows/timeline). `planner-ui.mjs` renders estimates using safe DOM text. Existing `directory.mjs`, `importer.mjs`, `tour.mjs` and `projects.mjs` extend their current contracts. `app.js`, HTML and CSS connect these to current controls. No production dependencies, accounts, databases, keys or new services.

The v2 store and full backup remain compatible. Existing unknown optional fields do not invalidate old records. JSON stop exports retain new allowlisted fields and `lng` imports map to `lon`; older Explorer source year/attribution stay attached. Next-season duplication keeps personal preferences/pins/notes but resets seasonal verification, visit state and departure. The service-worker release cache contains every new runtime module; it never caches upstream geocoding/routing or private discovery artifacts. Curated catalog contents remain unchanged.

## Validation and known limits

Baseline: 71 Node tests passed. Expanded suites exercise the actual modules, including authorized/disabled feeds, missing rights/expiry, malformed/empty/oversized sources, failure reports/stale output cleanup, workflow permissions, optional schema safety, radius/no-location, source grouping/conflicts, stable identity, legacy seasonal data, preference/mandatory selection, viewing budgets, timeline legs, overnight/DST/zone checks, backups and project duplication. The browser suite adds desktop/mobile discovery, denied GPS, no bulk geocoding, suggestion review before mutation, routing, schedule recalculation, snapshots and complete IndexedDB archive download, alongside existing regressions.

Browser runs use installed Microsoft Edge/Chromium because the bundled Playwright browser is absent in this environment. External map/geocoder/router services are deterministic test fixtures. These are genuine browser DOM/storage/service-worker runs, **not live service or physical iPhone verification**. Layout screenshots are test artifacts under ignored `test-results/`. No upstream data was fetched by the discovery pipeline and no Action/Pages deployment was executed here.

Final local validation (2026-10-29): `npm test` **98/98 passed**; `npm run test:browser` **36 scenario groups passed** with Edge/Chromium 156.0.4314.50 at 1366px desktop, 390px mobile and existing 320px touch checks; `node scripts/fetch-feeds.mjs` returned `no-authorized-feeds-configured` with zero upstream requests; `git diff --check` passed. The original 71 Node tests remain passing. Initial browser setup failed because the bundled executable was absent; using the documented `GLOWROUTE_BROWSER_EXECUTABLE` resolved that environment issue. Two existing browser assertions were updated for intentionally expanded directory result counts and the additional optional-details control. No unresolved test failures remain. New cases cover visible source paste, source-year mismatch, rural addresses, duplicate-safe weekly append, opt-in historical imports, action-only snapshot fetching and failed refresh recovery, alongside retained references and pin-accuracy protection.

Deployment uses the existing root-of-main GitHub Pages setup; no build/settings change is required. Follow the release branch/PR and GitHub Actions results before treating the live site as updated. Verify Pages' update/reload behavior and a physical-device trip after publication. Do not turn on provider harvesting as part of deployment.

Deferred: source-specific HTML fetching pending independent rights and stable exports; bulk coordinate acquisition (service policy/privacy); hosted feeds/pictures (cost and complexity); local gallery/journal expansion and automatic complete legacy-tour/media migration (portable restoration and quota UX first); closed-stop removal automation (warnings preserve user control); normalized CSV and long Maps-link enhancements (lower priority). Nearby discovery cannot manufacture coverage: the current public catalog and legacy snapshot have no reliable supplied coordinates. Address-only manual planning and pin review remain practical alternatives.

Retirement is conditional on verified local backups/manual migration, not merely feature parity. Follow [the retirement checklist](RETIREMENT.md). The old repository and its workflows remain untouched.
